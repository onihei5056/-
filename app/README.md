# 不動産現地調査PWA

現地調査担当者がスマートフォンから不動産の現地調査内容を入力し、写真を登録し、元Excelに近い形式の
PDFを出力できる業務用PWA(Progressive Web App)です。iPhone・Androidのホーム画面に追加でき、
オフラインでも入力・写真登録ができます。

> **重要**: 本アプリの項目定義は、元となる「不動産調査シート_2026.3.1.xlsx」がセッションに提供されなかったため、
> 一般的な様式で仮実装しています。詳細は `../docs/open-issues.md`(要確認事項一覧)を必ずご確認ください。

---

## 1. 何を準備するか

- Node.js 20以上(推奨: 22)と npm がインストールされたパソコン(開発・ビルド用)
- アプリを公開するWebサーバー(レンタルサーバーのHTTPS対応領域、または社内Webサーバー)
  - 特別なサーバー言語(PHP/Node等)は不要です。ビルド後の静的ファイル(HTML/CSS/JS)を置くだけで動作します
  - **HTTPS必須**です(PWAのオフライン機能・ホーム画面追加はHTTPS配信でないと動作しません)
- スマートフォン(iPhone/Android)とPC、それぞれで動作確認するためのブラウザ(Safari/Chrome/Edge)

## 2. どのファイルを編集するか

| 変更したいこと | 編集するファイル |
|---|---|
| 入力項目の追加・変更・選択肢の変更 | `src/schema/sections.ts` |
| 擁壁調査の項目 | `src/pages/WallSurveyPage.tsx` |
| 写真区分・撮影注意事項 | `src/schema/sections.ts` の `PHOTO_CATEGORIES` |
| PDF帳票のレイアウト・見出し | `src/pdf/generator.ts`、`src/pdf/blocks.ts` |
| 画面の色・文字サイズ等の見た目 | `src/styles.css` |
| アプリ名・アイコン・PWA設定 | `vite.config.ts`(`VitePWA` の `manifest`)、`public/icons/` |
| 入力チェックのルール(必須/数値範囲/日付) | `src/utils/validation.ts` |
| 自動計算の計算式 | `src/utils/calc.ts`、各項目の `calc` 設定(`sections.ts`) |

詳しいフォルダ構成は `../docs/folder-structure.md` を参照してください。

## 3. ローカルで起動する方法

```bash
cd app
npm install       # 初回のみ。依存パッケージをインストールします
npm run dev        # 開発サーバーを起動します(http://localhost:5173)
```

スマートフォンの実機で確認したい場合は、PCとスマートフォンを同じWi-Fiに接続し、
`npm run dev -- --host` で起動して表示されるIPアドレス(例: `http://192.168.x.x:5173`)にスマホの
ブラウザからアクセスしてください(この方法はHTTPではないため、PWAのインストールや一部機能は
本番のHTTPS環境と挙動が異なる場合があります)。

## 4. サーバーへ配置する方法

1. 本番用ファイルをビルドします。

   ```bash
   cd app
   npm install
   npm run build
   ```

   `app/dist/` フォルダに、配布用の静的ファイル一式(`index.html`, `assets/`, `manifest.webmanifest`,
   `sw.js` 等)が生成されます。

2. `app/dist/` フォルダの中身をまるごと、Webサーバーの公開ディレクトリ(例: `public_html/survey/` 等)に
   アップロードします(FTP/SFTP、レンタルサーバーのファイルマネージャ等をご利用ください)。

3. HTTPSでそのURL(例: `https://example.com/survey/`)にアクセスし、正常に案件一覧が表示されることを
   確認します。

4. サブディレクトリに配置する場合(例: `/survey/` 配下)は、`vite.config.ts` の `base: './'` の設定に
   より相対パスでビルドされているため、基本的に追加設定は不要です。ルート直下(`/`)に配置する場合も
   そのまま動作します。

5. 本アプリはクライアントサイドルーティングに `HashRouter`(URLに`#`を使う方式)を採用しているため、
   一般的な静的ホスティング(Apache/Nginx/レンタルサーバー標準設定)で追加のリライト設定なしに
   そのまま動作します。

## 5. データ保存先の設定方法

本バージョンのデータ保存先は**利用者のスマートフォン/PC内のIndexedDB(ブラウザ内データベース)のみ**です。
サーバー側にデータベースを用意する必要はありません(=一般的なレンタルサーバーでも動作する理由です)。

- 写真も含め、すべてのデータは端末内に保存されます。サーバーには一切送信されません。
- 複数端末でのデータ共有が必要な場合は、現時点では以下のいずれかの運用でカバーしてください。
  - 案件ごとにPDFを出力し、社内共有ドライブ等で共有する
  - 同一端末を複数人で使い回す(その場合は設定画面でPINロックの利用を推奨)
- 将来的にサーバー同期機能を追加したい場合は `docs/db-design.md` の「複数端末編集時の扱い」を参照し、
  同じテーブル構成を踏襲したAPIを追加することを推奨します。

## 6. PDF帳票を修正する方法

PDFのレイアウトは `src/pdf/generator.ts` と `src/pdf/blocks.ts` で組み立てています。

- 見出しの色・文字サイズ・表の罫線等の見た目を変えたい → `src/pdf/blocks.ts` の
  `buildTitleBlock` / `buildFieldsTableBlock` / `buildPhotoBlock` 内のスタイル(`style`オブジェクト)を編集
- ページに載せる項目・順番を変えたい → `src/pdf/generator.ts` の `buildBlocks` 関数を編集
  (`SECTIONS` をループして各グループの表を作っている箇所です)
- ヘッダー・フッターの内容(案件名/ページ番号等)を変えたい → `src/pdf/generator.ts` の
  `addHeaderFooter` 関数を編集
- 修正後は `npm run build` でビルドし、「PDFプレビュー」画面で見た目を確認してください。

## 7. 項目を追加または変更する方法

1. `src/schema/sections.ts` を開きます。
2. 追加したい大分類(`SectionDef`)または中分類(`SubGroup`)、項目(`FieldDef`)を見つけて編集します。
   既存の項目定義をコピーして `id` を新しいユニークな値に変更するのが簡単です。
3. 項目の種類(`type`)は以下から選べます。

   | type | 内容 |
   |---|---|
   | `text` | 1行テキスト |
   | `textarea` | 複数行テキスト |
   | `number` | 数値(スマホでは数字キーボードが開きます) |
   | `date` | 日付選択 |
   | `radio` | 単一選択(セグメントボタン。「有/無」等) |
   | `checkbox-multi` | 複数選択(選択ボタン) |
   | `select` | プルダウン選択 |
   | `calc` | 自動計算項目(`calc`プロパティで計算式を指定) |

4. 条件分岐を付けたい場合は `condition: { fieldId: '対象項目のid', equals: '値' }` を追加します。
5. 写真区分を追加・変更したい場合は同ファイルの `PHOTO_CATEGORIES` 配列を編集します。
6. 保存後、`npm run dev` で画面に反映されることを確認してください。項目定義書(`docs/item-definitions.md`)は
   このファイルから内容を転記して作成しているため、大きく変更した場合はあわせて更新してください。

## 8. バックアップ方法

本バージョンには自動バックアップ機能はありません。以下を運用上のバックアップ手段としてください。

- 調査完了時に必ずPDFを出力し、社内の共有ドライブ・ファイルサーバーに保存する
- 重要な案件は「複製」機能でコピーを残してから編集する
- 端末の入れ替え・初期化前には、対象端末の全案件のPDFを出力し終えていることを確認する

より高度なバックアップ(全データのエクスポート/インポート)が必要な場合は、`docs/open-issues.md` の
該当項目を参照し、機能追加を検討してください。

## 9. トラブル発生時の確認方法

| 症状 | 確認・対処方法 |
|---|---|
| 画面が真っ白になる | ブラウザのキャッシュ/サイトデータをクリアして再読み込み。それでも直らない場合は`npm run build`のやり直しとファイルの再アップロードを確認 |
| ホーム画面に追加できない | HTTPSで配信されているか確認(HTTP不可)。iPhoneはSafari、Androidは Chromeでのみ動作します |
| 保存したはずのデータが消えた | ブラウザの「サイトデータを削除」操作をしていないか確認。プライベート/シークレットブラウジングでは保存されません |
| 写真が登録できない | ブラウザのカメラ/写真へのアクセス許可設定を確認してください(端末設定 > ブラウザ > カメラ/写真) |
| PDFが真っ白/生成に失敗する | 一度「入力内容確認」画面に戻り、再度「PDFプレビュー」を開いて「再出力」を試してください。改善しない場合はブラウザの開発者ツール(コンソール)のエラーメッセージを確認してください |
| 新しいバージョンが反映されない | 表示される「更新する」通知をタップしてください。表示されない場合はブラウザを完全に閉じて再度開いてください |
| 特定の端末だけ動作がおかしい | ブラウザのバージョンが古い可能性があります。最新のSafari/Chrome/Edgeへの更新をお試しください |

解決しない場合は、`docs/` 配下の各ドキュメント(特に `docs/open-issues.md`)を確認のうえ、
開発担当者へ状況(端末機種・OSバージョン・ブラウザ・発生手順)を伝えてください。

## 技術構成(参考)

| 項目 | 採用 | 理由 |
|---|---|---|
| フロントエンド | React 18 + TypeScript + Vite | 型安全性、ビルドの速さ、静的ファイルとして配布可能 |
| PWA | vite-plugin-pwa(Workbox) | Manifest/Service Worker生成を自動化 |
| データ保存 | IndexedDB(Dexie.js) | サーバー不要でオフライン完結、レンタルサーバーでも動作 |
| PDF生成 | jsPDF + html2canvas | 日本語フォント埋め込み不要で文字化けを確実に回避(画面をそのまま画像化してPDF化する方式) |
| ルーティング | react-router(HashRouter) | 静的ホスティングでサーバー側リライト設定が不要 |

サーバーAPI・DBサーバーは今回のスコープでは採用していません(理由: 「特定のクラウドサービスが必須に
ならない構成」「一般的なレンタルサーバーに配置しやすい構成」という要件を優先したため)。将来的な
サーバー同期の追加方針は `docs/security.md` および `docs/db-design.md` を参照してください。
