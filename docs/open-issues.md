# 未確定事項および要確認事項一覧

## 最重要: 元Excelファイル未提供

セッション開始時に「不動産調査シート_2026.3.1.xlsx」の実体が提供されなかったため、ユーザーへの確認の結果
「ファイルなしで一般的な様式で進める」との指示に基づき、本アプリの全項目・選択肢・単位・注意書き・
帳票レイアウトは**一般的な不動産現地調査シートの標準様式からの仮定義**です。

**実際のExcelが提供された場合、以下すべてを実ファイルの内容で置き換える必要があります。**

- `app/src/schema/sections.ts` … 項目定義本体(ラベル・選択肢・単位・条件分岐・必須要否)
- `app/src/pages/WallSurveyPage.tsx` … 擁壁調査の項目
- `app/src/schema/sections.ts` の `PHOTO_CATEGORIES` … 写真区分・撮影注意事項
- `app/src/pdf/generator.ts` / `app/src/pdf/blocks.ts` … PDF帳票レイアウト(実際の帳票の見出し・並び順・罫線構成に合わせる)
- `docs/item-definitions.md` / `docs/mapping-table.md` / `docs/excel-analysis.md`(これらはコードから自動生成しているため、
  `sections.ts` 更新後に `docs`配下生成スクリプトの考え方に沿って再生成、または手動更新してください)

## 項目定義に関する要確認事項

- 各項目のラベル文言・選択肢の正式名称(例:「用途地域」の区分名、「地目」の区分名等)は仮の一般名称です。
- 数値項目の入力制限(最小値・最大値・桁数)は仮の値です。実際の業務上の妥当な範囲に調整が必要です。
- 条件分岐の発火条件(どの値のときにどの項目を表示するか)は要件文中の8例をそのまま実装していますが、
  それ以外の分岐(例: マンション調査事項の詳細分岐)は一般的に妥当と思われる内容を独自に追加しています。
- 「境界明示」「保管書類」「見積依頼」等、大分類名のみ指定され詳細項目の記載がなかったものは、
  一般的な不動産調査で使われる代表的な項目を仮に設定しています。

## 擁壁調査に関する要確認事項

- 「不具合箇所ごとの写真」について、本実装では擁壁単位(1擁壁=1写真ギャラリー)で写真を管理し、
  各写真にコメントを付けることで不具合箇所との対応を記録する設計としています。不具合箇所ごとに
  完全に独立した写真ギャラリーが必要な場合は設計変更が必要です。
- 「敷地図」「全景写真」は独立した専用アップロード欄ではなく、擁壁写真ギャラリー内に撮影方向・コメントで
  区別して登録する設計にしています。専用の別項目が必要か要確認です。

## 計算機能に関する要確認事項

- 建蔽率・容積率の計算式は一般的な計算式(建築面積/敷地面積、延床面積/敷地面積 × 100)を採用しています。
  緩和措置(角地緩和、防火地域内耐火建築物の割増等)を反映すべきかは要確認です。
- 延床面積合計は「地階＋1階＋2階＋3階以上」の単純合計です。容積率対象床面積(駐車場・地下室の緩和等)を
  別途考慮する必要があるかは要確認です。

## PDF帳票に関する要確認事項

- ページレイアウト(見出しバー、表形式、写真1枚1ページ相当のブロック単位配置)は一般的な調査報告書の
  体裁を参考にした仮デザインです。元Excelの罫線・フォント・列幅・押印欄等の再現は、実ファイル提供後に
  別途調整が必要です。
- 「非表示になった未使用項目」は原則PDF上で「-」表記としています。「無」表記が適切な項目(有無系の項目)か、
  完全に空欄が適切かは項目ごとに異なる可能性があり、実ファイルで確認が必要です。

## セキュリティ・認証に関する要確認事項(`docs/security.md` にも記載)

- 認証は端末共有時の簡易PINロックのみで、ユーザー単位のアクセス権限管理・監査ログの外部送信・
  暗号化ストレージ等は未実装です。本番の複数拠点運用では要件に応じた強化が必要です。
- バックアップ・誤削除復元の仕組みは未実装で、PDF出力による手動バックアップを暫定運用としています。

## サーバー同期に関する要確認事項

- 本バージョンは端末内IndexedDBのみで完結するオフラインファースト構成です。複数端末間のリアルタイム同期、
  楽観的排他制御による競合通知は設計方針のみ記載し、実装はしていません(`docs/db-design.md` 参照)。
- 実際にサーバー同期を追加する場合、認証方式・API設計・ホスティング先(自社サーバー/レンタルサーバー等)を
  別途決定する必要があります。

## その他

- サンプルデータの写真は実際の設備写真ではなく、区分名を描画したプレースホルダー画像です(著作権的に安全な
  仮画像として意図的にこの方式を採用しています)。動作確認用途としてご利用ください。
- 位置情報取得機能は要件通り「初期状態では取得しない」設計とし、本バージョンでは位置情報取得UI自体を
  実装していません(将来的に写真ごとのGPS付与が必要な場合は`PhotoRecord.gpsLat/gpsLng`フィールドを
  利用し、明示的な許可ダイアログを追加してください)。
