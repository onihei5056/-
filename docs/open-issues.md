# 未確定事項および要確認事項一覧

元Excel「不動産調査シート_2026.3.1.xlsx」を解析したうえで、**Excelの記載だけでは仕様が確定できず、
アプリ側で解釈・補完した箇所**の一覧です。運用開始前に業務担当者の確認をお願いします。

## A. シート構成に関する確認事項(最重要)

| No | 事項 | アプリでの扱い | 確認したいこと |
|---|---|---|---|
| A-1 | 現行版シート `不動産調査シート2026.3.1` は**役所調査から始まり、売主・面談情報／物件情報／法務局調査を含まない**。これらは**非表示**の旧版シート `不動産調査シート` にのみ存在する | 旧版シートの前半(2〜33行)を「売主・面談情報」「物件情報・権利関係」「法務局調査」として採用 | 現行運用では旧版シートの前半も併用しているか。それとも別ファイル・別様式に分離したか |
| A-2 | マンション調査事項は現行版にのみ存在 | 現行版の内容を採用 | 土地・戸建て案件でも画面に出るが、非表示にすべきか(現状は常時表示) |
| A-3 | 地盤補強(□無/□柱状改良/□鋼管杭/□砕石工法/□ベタ/□その他)は**旧版にのみ存在**し現行版では削除されている | 旧版から復活させて「周辺環境他」に配置(要確認フラグ付き) | 意図的に廃止した項目か。廃止なら削除する |
| A-4 | 旧版と現行版で内容が異なる項目がある(道路種別の記入形式、前面道路側溝→水路の変更、地域地区等に□風致地区/□その他が追加、その他法令に□屋外広告物条例/□河川法/□水防法が追加 等) | すべて**現行版(2026.3.1)を優先** | この優先順で問題ないか |

## B. 項目の解釈に関する確認事項

| No | 事項 | アプリでの扱い |
|---|---|---|
| B-1 | 「■本物件の建ぺい率：建築面積÷敷地面積＝　　%」の**建築面積**を入力する欄が元Excelに無い | 「建築面積」欄を新設し、建ぺい率を自動計算(要確認フラグ付き)。Excelの注記「※1Fより2Fの面積が広い場合は2F面積で算出」を画面とPDFに表示 |
| B-2 | 容積率の注記「※前面幅員4m未満の場合は4mとみなし算出」は、幅員による容積率低減の計算を指す可能性がある | 自動計算は「延床面積÷敷地面積×100」のみ。低減計算は未実装で、注記を表示して手動修正で対応 |
| B-3 | 道路種別欄は現行版が「■　　側幅員　　ｍ(　　)」×2組×2行、間口×3、方位別の道路区分×4行 | 幅員①〜④・間口①〜③・方位①〜④として実装 |
| B-4 | ラベルの無い空チェックボックス(□のみ)が各所にある(地域地区等・工法・材質・排水設備・変状・その他法令 等) | 「その他」＋自由入力欄として実装 |
| B-5 | 「退去時期(目安)」は「■　年　月　日頃 □売却決定後 □(空欄)」 | 日付指定/売却決定後/その他 の3択＋日付欄・自由入力欄 |
| B-6 | 「引越先斡旋(要/不要)」は「→未・未定の場合」に確認する項目 | 条件分岐が複数項目にまたがるため常時表示＋注記 |
| B-7 | 建築年月日は「[昭/平/令/西暦]　年　月　日」 | 元号の選択＋日付ピッカーの2項目。PDFは西暦で出力 |
| B-8 | 契約不適合は「□有 □免責 □インスペクション」の並列チェック | 複数選択として実装(排他ではない前提) |

## C. 写真に関する確認事項

| No | 事項 | アプリでの扱い |
|---|---|---|
| C-1 | 設備現況写真シートの枠は6つ(上水道/メーター/汚水/雨水/ガス/電気)だが、注意事項には【下水】【浄化槽】の記載がある | 下水・浄化槽・その他設備の区分を追加(画面に「帳票枠外」と明示)。排水方式に応じて未登録なら警告 |
| C-2 | 「※契約審査時、枠内に収まらない場合は別途写真を添付する」 | 1区分に何枚でも登録可能。PDFは2列グリッドで自動的にページを継ぎ足す |
| C-3 | 免責文の「築年数が39年経過しており」は案件ごとに変わる値 | 案件ごとに築年数を入力し、PDFの文面へ差し込み |
| C-4 | 撮影日(C40)・撮影者(H40)はシート単位で1つ | 写真ごとに撮影日時・撮影者を保持し、PDFでは最古の撮影日と撮影者一覧を出力 |
| C-5 | 擁壁の写真枠は「敷地図・撮影方向」「①②③全景」「④⑤不具合箇所(箇所名記入)」 | 3区分として実装し、不具合箇所の写真には箇所名を保持。枚数は3枠・2枠に限定せず複数登録可 |

## D. セキュリティ・運用に関する未実装事項

`docs/security.md` に詳細を記載しています。要点のみ再掲します。

- 利用者ごとのアクセス権限管理(RBAC)は未実装。現状は端末ロック用の簡易PINのみ
- 入力データのアプリケーション層での暗号化は未実装(ブラウザのIndexedDB保護に依存)
- 写真・データはすべて端末内保存。サーバー同期・複数端末間の競合解決は設計方針のみ(未実装)
- バックアップは**書き出し機能で対応済み**(設定画面から写真を含む全案件をJSONファイルへ書き出し、
  別端末・別URLのアプリで取り込んで復元できる)。定期的な書き出しと保管は運用ルールで担保すること
- 削除は物理削除。ゴミ箱/復元機能は未実装

| No | 事項 | アプリでの扱い | 確認したいこと |

| F-2 | ①役所調査・②物件調査・③物件状況に入れる項目が未定 | 既存の調査シートの画面を内容の近い大項目へ割り当て(`docs/ui-sections.md` 参照) | 法務局調査を①役所調査に入れてよいか。売主・面談情報を③物件状況としてよいか |

## E. その他

- サンプル案件の写真は区分名を描画したプレースホルダー画像です(実写真ではありません)。
- 位置情報は要件どおり初期状態では取得せず、取得UIも実装していません(`PhotoRecord.gpsLat/gpsLng` の枠のみ用意)。
- 擁壁調査シートの備考欄にあった重要事項説明の長文サンプル(A42)は、案件ごとに内容が異なるため
  初期値としては投入せず、自由記述欄としています。
- 旧版シートに含まれる「受益者負担金」「工作物建確検済」等の脚注参照(※12〜※20)は、
  該当項目の注記としてアプリ画面・PDFの両方に表示しています。
