# データ管理とセキュリティ

不動産情報・売主情報・住所・写真等の個人情報/機密情報を扱うため、要件に基づき実装済み事項と、
本バージョンでは設計方針のみ明記し実装を見送った事項を分けて記載します。

## 実装済み

| 項目 | 内容 |
|---|---|
| HTTPS前提 | 本アプリはService Worker(PWA)を利用するため、HTTPSでの配信が前提です(localhostのみ例外)。`docs/../app/README.md` のデプロイ手順もHTTPS配信を前提に記載しています。 |
| 認証機能(簡易) | 端末ロック用の簡易PIN(`app/src/utils/auth.ts`, `AuthGate.tsx`)。SHA-256でハッシュ化してlocalStorageに保存し、平文PINは保存しません。 |
| 再認証(タイムアウト) | 15分操作がないと自動的に再ロックされます(`IDLE_TIMEOUT_MS`)。 |
| ログアウト | 設定画面から「今すぐロックする(ログアウト)」でその場でロック状態に戻せます。 |
| 作成者/更新者/作成日時/更新日時 | `SurveyCase.createdBy/updatedBy/createdAt/updatedAt`、`PhotoRecord`/`WallSurveyRecord`も同様に保持。 |
| 操作履歴 | `auditLogs` テーブルに、案件作成・複製・写真追加削除・擁壁追加削除・PDF出力等を記録。 |
| 削除時の確認 | 案件削除・写真削除・擁壁削除はいずれも確認ダイアログを表示してから実行。 |
| オフラインデータの無制限保持防止 | 写真は既定で圧縮後画像のみ保持(原本保持は明示的なオプトイン設定)。案件削除時は関連データを連鎖削除。 |

## 設計方針としての明記(未実装・本番導入時に対応が必要)

要件13で「実装または設計書に明記」とされている項目のうち、本バージョンのスコープでは
以下は実装を見送り、方針のみ記載します。これらは `docs/open-issues.md` にも要確認事項として掲載しています。

- **利用者ごとのアクセス権限管理**: 現状は端末単位の簡易PINロックのみで、ユーザー単位のロールベース
  アクセス制御(RBAC)は未実装です。複数拠点・複数担当者での本格運用時は、社内IdP(Azure AD/Google Workspace等)
  やOAuth2による認証・認可をサーバーAPI層に追加し、案件ごとの閲覧・編集権限(担当者本人/上長/管理者)を
  設けることを推奨します。
- **入力データの暗号化方針**: IndexedDBはブラウザの保護機構(オリジン分離、端末ロックとの連動)に依存しており、
  アプリケーション層での追加の暗号化(例: Web Crypto APIによるAES-GCM暗号化)は本バージョンでは未実装です。
  機密性要件が高い場合は、保存前にフィールド単位で暗号化し、復号鍵をサーバー側で管理する方式への
  拡張を推奨します。
- **写真保存先**: 本バージョンは端末内IndexedDBのみに保存します(クラウドアップロードなし)。
  サーバー同期を追加する場合は、S3互換オブジェクトストレージ等、特定クラウドに依存しない保存先を
  選定し、アクセスURLの署名付き発行(有効期限付き)を行う設計を推奨します。
- **案件の閲覧権限**: 現状は同一端末内であれば全案件を閲覧可能です。担当者ごとに閲覧範囲を分ける場合は
  サーバー側でのテナント/担当者スコープの導入が必要です。
- **バックアップ方法**: 設定画面の「データの書き出し・取り込み」で、写真を含む全案件を
  1つのJSONファイルへ書き出せます(`app/src/utils/backup.ts`)。書き出したファイルは別端末・別URLの
  アプリで取り込んで復元できるため、機種変更・配置先変更・サイトデータ削除に備えられます。
  ファイルには売主情報・写真がそのまま含まれるため、保管場所のアクセス制限に注意してください。
  取り込みは既存データを上書きせず、ID重複時は別案件として追加します。
- **誤削除からの復元方針**: 削除は確認ダイアログを経ますが、削除後の復元機能(ゴミ箱/論理削除)は
  本バージョンでは未実装の物理削除です。誤削除対策が必要な場合は論理削除(`deletedAt`フラグ)方式への
  変更を推奨します。

## 端末内オフラインデータの取り扱い

- 端末ロック(PIN)未設定の場合、端末を他者が操作するとデータが閲覧可能です。現場での共有端末利用時は
  設定画面からPINロックの設定を強く推奨します。
- ブラウザの「サイトデータを削除」操作でIndexedDBの内容は失われます。定期的なPDF出力・共有をもって
  実質的なバックアップとする運用を推奨します。
- 写真原本(オプトイン設定時のみ保持)は容量を多く使用するため、既定ではOFFにしています。

## 今後サーバー同期を追加する場合の指針

`docs/db-design.md` のテーブル構成をそのままAPIのリクエスト/レスポンス形にマッピングできる設計にしています。
`SurveyCase.version` を用いた楽観的排他制御(サーバー側のversionと不一致なら409を返し、クライアントは
「後から保存した内容で無条件に上書きしない」ため競合画面を表示する)方式を想定してください。
