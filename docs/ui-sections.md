# 画面構成(UI構成について.xlsx)と修正手順

出典: **UI構成について.xlsx**(シート「大項目」「付帯設備表」)。
このExcelの大項目①〜④を**アプリ全体の目次**とし、既存の入力画面をその下にぶら下げる形に統合しました。

---

## 1. 目次の構成

目次は2段になっています。

- **1段目** … 大項目(①〜④)を横並び。タップするとその中の小項目が下に出てきます
- **2段目** … 開いている大項目に属する入力画面(小項目)

| 大項目 | 小項目(入力画面) |
|---|---|
| **①役所調査** | 役所調査(都市計画法・建築基準法など) / 飲用水・電気・ガス・排水施設 / 法務局調査 |
| **②物件調査** | 物件情報・権利関係 / 周辺環境他 / マンション調査事項 / 設備現況写真 / 擁壁調査 |
| **③物件状況** | 売主・面談情報 |
| **④付帯設備表** | (この大項目自体が入力画面) |

「戻る/次へ」でたどる順序も上の表のとおりです。最後に「入力内容確認」→「PDFプレビュー」と続きます。

### 大項目は①〜④で確定

アプリの大項目は**①役所調査・②物件調査・③物件状況・④付帯設備表の4つで確定**です
(この4つ以外に大項目は増やさない前提)。
目次1段目に並ぶ「入力内容確認」「PDF出力」は大項目ではなく、入力後の操作です。

### 各画面をどの大項目に入れたか(変更可)

- 元々あった「役所調査(都市計画法・建築基準法など)」の画面を**そのまま①役所調査の中身**としました
  (同名の画面を2つ作らないため)
- 法務局調査は公的機関での調査として**①**に入れています。②へ移す場合は下記の1行を移すだけです
- 売主からの聞き取り(売主・面談情報)を**③物件状況**としました
- 設備現況写真・擁壁調査は現地で確認するものとして**②物件調査**に入れています

### 項目が重複したときの方針

同じ内容の項目が「④付帯設備表」と他の大項目の両方に出てくる場合は、
**④付帯設備表の側を正**とし、他方には作りません(二重入力を避けるため)。
現時点で元の不動産調査シートに付帯設備表と重複する項目はありませんでした
(設備現況写真は「写真」、付帯設備表は「設備の有無」なので重複ではありません)。

## 2. どのファイルを触ると何が変わるか

| 触るファイル | 変わるもの |
|---|---|
| `app/src/schema/uiSections.ts` | **大項目の並び順・名称・どの画面がどの大項目に属するか**(目次・前後移動・進捗に自動反映) |
| `app/src/schema/sections.ts` | 各入力画面の項目(全244項目) |
| `app/src/schema/fittings.ts` | 付帯設備表の行(中項目・小項目・選択肢) |
| `app/src/components/FittingsForm.tsx` | 付帯設備表の見た目・入力部品の挙動 |

**画面を別の大項目に移したいときは `uiSections.ts` の `children` の配列から移すだけです。**

```ts
{ id: 'ui-city-office', title: '①役所調査', kind: 'group',
  children: ['city-office', 'utilities', 'registry'] },   // ← ここを並べ替える/移す
```

新しい大項目を足すときも、この配列に1行足せば目次・URL・進捗集計まで揃います。

## 3. 付帯設備表の作り

Excelの **2行目〜48行目(47行)をそのままの並び順**で画面にしています。

| Excel列 | 画面での扱い |
|---|---|
| A 大項目 | 画面タイトル(④付帯設備表) |
| B 中項目 | 開閉式の見出し。**空欄の行は直前の中項目に属する**ものとして補完 |
| C 小項目 | 入力行の見出し |
| D チェック方式 | `チェックボックス` / `自由記載` の指定。**この文字列自体は入力欄にしない** |
| E 項目名 | 「有・無」など。**1つだけ選択**(もう一度押すと選択解除) |
| F 2項目目 | 「・」で区切って選択肢に分解。**既定は複数選択** |
| G 追加自由入力項目 | 見出し＋自由入力欄。**記載がある行だけ表示** |
| H | 「判明している故障・不具合の具体的内容(自由記載)」。**全ての入力行に表示** |

### F列の例外(1つだけ選択にしているもの)

`app/src/schema/fittings.ts` の `FITTINGS_EXCLUSIVE_F` に列挙しています。

- `鏡有・鏡無`(浴室洗面台)
- `モニター：有・無`(インターホン)

これ以外のF列は複数選択です。排他にしたいものが増えたら、この配列に文字列をそのまま追加します。

### 「：」より前は見出しになる

`給湯箇所：キッチン・浴室・洗面所` のように「：」がある場合、
`給湯箇所：` を見出しとして表示し、選択肢は `キッチン` `浴室` `洗面所` の3つになります。

### 自由記載の行(備考)

D列が `自由記載` の行(**30行目と48行目**)は、選択肢を持たない自由記述欄です。
中項目名がどちらも「備考」ですが、**行番号で区別しているため別々に保存されます**。

## 4. 入力内容の保存のしかた

他の画面と同じ `sectionAnswers` テーブルに、画面ID(`ui-fittings`)をキーにして保存します。
項目ごとのキーは**Excelの行番号**を含みます。

```
r2_e    … 2行目のE列の選択       (例: "有")
r2_f    … 2行目のF列の選択       (複数選択は配列 例: ["キッチン","浴室"])
r2_g    … 2行目のG列の自由入力
r2_h    … 2行目のH列(故障・不具合)
r30_text … 30行目(備考)の自由記載
```

このため、**中項目名や小項目名が重複していても入力内容が混ざることはありません**
(例: 「混合水栓」はキッチン設備5行目と浴室設備14行目にありますが、`r5_e` と `r14_e` で別物)。

> **注意**: `fittings.ts` の `row` はそのまま保存キーになります。
> 行を並び替えても `row` の値は変えないでください(既に入力済みのデータが読めなくなります)。
> 行を新しく足す場合は、既存の行番号と重ならない番号を付けてください。
