## 1. 何を作ったか

不動産の現地調査を、紙やExcelの代わりに**スマートフォンから入力し、写真を登録し、
元Excelに近い帳票のPDFを出力する**業務用PWA(Webアプリ)。

- 公開URL: `https://onihei5056.github.io/-/`
- リポジトリ: `https://github.com/onihei5056/-` (public)
- 稼働状況: **iPhoneのホーム画面から起動して実際に動作する状態**まで完了

### 設計上の最重要方針

**調査データ・写真・売主情報は一切サーバーへ送信しない。** すべて利用者の端末内(IndexedDB)にのみ保存する。
この方針により、レンタルサーバーや静的ホスティングだけで完結し、個人情報の外部流出経路を持たない。
その代償として **端末間でデータは共有されない**(同じURLを別の端末で開いても中身は別)。
共有手段はPDF出力のみ。

## 2. 技術構成

| 領域 | 採用技術 | 備考 |
|---|---|---|
| フロントエンド | React 18 + TypeScript + Vite | `app/` 配下 |
| ルーティング | react-router (**HashRouter**) | 静的ホスティングでリライト設定不要にするため |
| データ保存 | IndexedDB (**Dexie**) | サーバーDBなし |
| PDF生成 | **jsPDF + html2canvas** | 日本語フォント埋め込み不要(DOMを画像化する方式)で文字化けを確実に回避 |
| PWA | vite-plugin-pwa (Workbox) | Manifest/Service Worker自動生成、更新通知あり |
| 公開 | GitHub Pages + GitHub Actions | `main` への push で自動ビルド・自動公開 |

サーバーAPI・認証基盤・DBサーバーは**意図的に採用していない**(要件「特定クラウド必須の構成を避ける」「レンタルサーバーに配置しやすく」を優先)。

## 3. 元Excelの解析結果(引き継ぎで最も失われやすい知識)

出典: **不動産調査シート_2026.3.1.xlsx**(全4シート)。
**このファイルはリポジトリに含めていない**(リポジトリがpublicのため、業務ノウハウを公開しない判断)。
引き継ぎ時は**必ず現物を別途渡すこと**。

### シート構成と重要な発見

| シート | 状態 | 内容 |
|---|---|---|
| `不動産調査シート2026.3.1` | 表示 (印刷範囲 A1:J74) | **現行版**。役所調査/供給施設/周辺環境/マンション調査事項 |
| `設備現況写真` | 表示 | 写真6枠(2列×3行)＋撮影日/撮影者＋撮影注意(K・L列)＋免責文 |
| `擁壁調査シート` | 表示 | 擁壁1面ごとの帳票。左=チェック項目、右=写真6枠 |
| `不動産調査シート` | **非表示** | **旧版**。売主/面談情報・物件情報・法務局調査＋脚注※1〜※20 |

**注意すべき点(そのまま引き継ぐこと):**

1. 現行版シートには**売主・面談情報/物件情報/法務局調査が存在しない**。非表示の旧版シートにのみある。
   本アプリは「現行版 ＋ 旧版の前半 ＋ 旧版の地盤補強」を合成した構成にしている。
2. マンション調査事項は**現行版のみ**、地盤補強は**旧版のみ**。
3. 全4シートとも **数式0件・入力規則0件・セルコメント0件**。すべて「□チェックボックス＋全角スペース記入欄」。
   建ぺい率・容積率・延床面積合計も数式ではなく記入欄だったため、**アプリ側で自動計算に変更**している。

詳細は `docs/excel-analysis.md`。

## 4. リポジトリ構成(どこを触ると何が変わるか)

```
/
├── app/                          … アプリ本体
│   ├── README.md                 … セットアップ〜配置〜保守の手順(非技術者向け)
│   └── src/
│       ├── schema/sections.ts    … ★項目定義の本体(全244項目)。元Excelのセル番地付き
│       ├── schema/wall.ts        … 擁壁調査の選択肢定義
│       ├── schema/flow.ts        … 入力ステップの順序
│       ├── pages/                … 画面(SectionPageが項目定義から自動生成)
│       ├── pdf/                  … ★PDF帳票の生成(generator.ts / blocks.ts)
│       ├── utils/validation.ts   … 入力チェック(エラー/警告の分類)
│       ├── utils/calc.ts         … 自動計算(セクション横断参照に対応)
│       └── db/db.ts              … IndexedDB定義
├── docs/                         … 設計ドキュメント一式(本ファイル含む)
├── download/                     … ビルド済みZIP(自社サーバー配置用。古くなる点に注意)
└── .github/workflows/deploy-pages.yml … 自動公開の設定
```

**項目の追加・変更は原則 `app/src/schema/sections.ts` の編集だけで完結する**(画面もPDFも自動追従)。
擁壁調査のみ帳票構造が特殊なため専用画面 `app/src/pages/WallSurveyPage.tsx` で個別実装。

## 5. 開発〜反映の手順

```bash
cd app
npm install
npm run dev     # 開発サーバー (http://localhost:5173)
npm run build   # 本番ビルド → app/dist
```

反映フロー:

1. コードを修正
2. `main` ブランチに反映(PRを作成 → マージ、が本プロジェクトの慣習)
3. GitHub Actionsが自動でビルドし、GitHub Pagesへ公開(3〜5分)
4. 利用者の端末に「新しいバージョンがあります」と通知が出る → タップで更新

**利用者の入力済みデータはアプリ更新では消えない。**

## 6. 運用上の重要な制約

| 制約 | 内容 |
|---|---|
| 端末間でデータ共有不可 | 各端末に独立して保存。共有手段はPDFのみ |
| URLが変わるとデータを引き継げない | 別サイト扱いになるため。**ホスティング移行は本番運用開始前に行うべき** |
| iOSのデータ自動削除 | 対策として起動時に `navigator.storage.persist()` を要求。設定画面で保護状態を確認可能 |
| リポジトリがpublic | 調査項目の構成・社内向け注意書きが閲覧可能な状態。本番運用時は自社サーバー等への移行を推奨 |
| 配置用ZIPは古くなる | `download/` のZIPはスナップショット。最新は `npm run build` で生成すること |

## 7. 未実装・要確認事項

**必ず `docs/open-issues.md` を読むこと。** 主要なものは以下。

### 業務確認が必要(Excelの記載だけでは確定できなかった箇所)
- 現行シートに売主情報が無い件(旧版シートを併用しているのか、別様式に分離したのか)
- 地盤補強を意図的に廃止したのかどうか
- 建ぺい率算出用の「建築面積」欄が元Excelに無いため、アプリで新設している点
- 容積率の「前面幅員4m未満の場合は4mとみなし算出」は低減計算未実装(手動修正で対応)

### 未実装機能
- サーバー同期、複数端末間の競合解決
- 利用者ごとのアクセス権限管理(現状は端末ロック用の簡易PINのみ)
- 保存データの暗号化(ブラウザの保護機構に依存)
- 全データのエクスポート/インポート(バックアップはPDF出力で代替)
- 削除の取り消し(現状は物理削除)
- 写真の位置情報取得(要件により初期状態では取得しない方針)

## 9. 他のAIアシスタント(ChatGPT等)に引き継ぐ場合の注意

- リポジトリはpublicのため、URLを伝えれば内容を読ませることは可能(ブラウジング機能が必要)。
- ただし**チャット型AIは通常、リポジトリへ直接コミット・プッシュできない**。
  コードを受け取って自分でコミットするか、エージェント機能(Codex等)でGitHub連携を設定する必要がある。
- ビルド確認(`npm run build`)や実機での表示確認を、AI側の環境で行えるかは事前に確認すること。
  本プロジェクトは「ビルドが通る」だけでなく「iPhoneの実画面で崩れない」ことが重要(ステータスバーへの潜り込み等、実機でしか出ない不具合が実際に発生している)。
- 会話履歴には引き継げない判断の経緯が含まれる。本ファイルと `docs/open-issues.md` がその要約になっている。
